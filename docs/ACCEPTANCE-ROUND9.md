# 第九批：按原生事件时间计算蓄力，排除松开排队时间

日期：2026-11-10。基线：`622d96d9b9699d7f39add8020dde3fd4ee750400`。本批只处理已证实的输入计时问题，不改轨迹公式、速度/射程映射、落地判定、素材或存档规则。

## 真实浏览器确认

第八批曾观察到事件间隔约 59.4 ms、消费后蓄力约 115.6 ms。本批用小型受控实验确认机制：真实鼠标、空格键或触控按下后，在页面执行实际的 200 ms 主线程忙循环，同时从宿主发送真实松开输入。所有事件均由浏览器生成、`isTrusted=true`；没有传入 CDP timestamp 参数、修改事件属性或用自动化请求时长代替事件时间。

基线使用 `performance.now()-pressWall`，会把松开已经发生但尚未被 JS 消费的等待时间算入蓄力。三个输入类型均复现了约 150 ms 的额外时长和更远落点。

| 输入 | 基线真实事件间隔 | 基线蓄力 / 射程 | 本批真实事件间隔 | 本批蓄力 / 射程 |
| --- | ---: | ---: | ---: | ---: |
| 鼠标，受控阻塞 | 57.1 ms | 205.7 ms / 5.47 | 52.9 ms | 52.9 ms / 1.41 |
| 空格，受控阻塞 | 51.8 ms | 202.8 ms / 5.40 | 53.2 ms | 53.2 ms / 1.41 |
| 触屏，受控阻塞 | 63.1 ms | 220.2 ms / 5.86 | 72.1 ms | 72.1 ms / 1.92 |

每次真实间隔并非都恰好 50 ms，所以不要求不同运行的射程强行相同。验证使用每次原生事件自身的间隔，检查 `flight.hold`，再将该间隔代入未改动的压缩、速度和圆整射程公式。这样区分真正更长的按住时间与事件消费排队延迟。

[完整原始输入、阻塞区间和落点数据](qa/round9/queue-results.json)。本次最终运行各排队条件首次均满足超过 100 ms 的真实消费延迟；脚本仅在没有实际排队时允许一次有记录的设置重试，不能通过丢弃错误落点或不满足时序条件来宣称覆盖。

## 实现与边界

`eventInputTime` 将可用的页面相对时间戳或带可靠 `performance.timeOrigin` 的 epoch 时间戳归一化到当前文档时钟。按下时保存事件时间；松开时用原生事件间隔计算蓄力，并把同一时长传给释放姿态计算。准备中的压缩也采用对应起点，避免只改调试数值、实际姿态仍使用错误时长。

| 情况 | 行为 |
| --- | --- |
| 两端均可归一化 | 使用两端原生时间戳之差 |
| 时间戳缺失、0、非数、未来值，或 epoch 缺少可用 origin | 使用完整的处理时间起止对，保持兼容；不混合两种时钟 |
| 松开早于当前按下，或有效输入早于取消/暂停边界 | 忽略迟到输入，不能消费新一轮蓄力 |
| 菜单、重启、取消、丢失捕获 | 清理本次输入时钟；恢复时更新输入边界 |
| 空格重复按下 / 重复松开 | 不重置起点，不重复发起跳跃 |

保留原有速度、压缩上限和射程公式，不对实际长按做请求时长裁剪。2.2 秒请求在最终实验中的原生间隔约 2205.4 ms，`flight.hold` 同样完整记录约 2205.4 ms。宿主等待 RPC 导致实际更长的按住时间，仍会作为真实输入计算；本次不将这类情况视为产品错误。

时间戳域、缺失/无效值及迟到输入的测试使用纯函数/VM 数值夹具，并非伪造真实浏览器事件。真实浏览器部分只验证了本次 Chromium 的页面相对事件时间戳。Safari/实体设备的实际时间戳行为未验收；回退路径不承诺能消除不可用时间戳环境中的排队偏差，也无法恢复浏览器创建事件之前的设备或宿主延迟。
